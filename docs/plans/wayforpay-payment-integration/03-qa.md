## Critical Implementation Bug (blocking full coverage)

**Bug:** `(string) $payment->transaction_status` throws
`Error: Object of class App\Enums\PaymentStatusEnum could not be converted to string`
in PHP 8.1+.

Eloquent casts `transaction_status` to `PaymentStatusEnum` enum instance (via
`casts()`). Backed enums cannot be cast to string with `(string)` — you must use
`->value`.

**Affected files and lines:** | File | Line | Bad code | Fix |
|------|------|----------|-----| | `app/Jobs/HandlePaymentWebhookJob.php` | 61 |
`PaymentStatusEnum::tryFrom((string) $payment->transaction_status)` |
`$payment->transaction_status instanceof PaymentStatusEnum ? $payment->transaction_status : PaymentStatusEnum::tryFrom((string) $payment->transaction_status)`
or simply remove the tryFrom wrapper since the value is already an enum | |
`app/Actions/Payments/RefundPaymentAction.php` | 21 |
`PaymentStatusEnum::tryFrom((string) $payment->transaction_status)` | same | |
`app/Actions/Payments/CheckPaymentStatusAction.php` | 22 |
`PaymentStatusEnum::tryFrom((string) $payment->transaction_status)` | same | |
`app/Actions/Payments/PaymentSuccessPage.php` | 32 |
`PaymentStatusEnum::tryFrom((string) $payment->transaction_status)?->value` |
`$payment->transaction_status?->value` | |
`app/Actions/Payments/PaymentFailurePage.php` | 33 | same pattern | same fix | |
`app/Actions/Payments/ListPaymentHistoryAction.php` | 88 | same pattern | same
fix |

**Simplest fix for all occurrences:** Replace
`PaymentStatusEnum::tryFrom((string) $payment->transaction_status)` with
`$payment->transaction_status` (the cast already returns a `PaymentStatusEnum`
instance or null).

### Open issues for security phase

1. **[CRITICAL] PHP TypeError in 6 Action/Job files** —
   `(string) $payment->transaction_status` fails at runtime. The webhook
   processing, refund, status check, and both result pages are completely broken
   for any payment with a non-null status that has been loaded from DB via
   Eloquent (which always casts it to enum). This means no payment can actually
   complete its lifecycle successfully after the PENDING state.
2. **[HIGH] `InitiatePaymentAction` — no test coverage** — the WayForPay
   `purchase()` call requires mocking the facade; not covered because the action
   is untested.
3. **[HIGH] `RefundPaymentAction` — no test coverage** — blocked by bug #1; once
   fixed, must test: APPROVED→REFUNDED transition, markUnpaid(), WFP mock
   returning `Refunded`, non-APPROVED payment returns false.
4. **[MEDIUM] Webhook HTTP endpoint not integration-tested** —
   `POST /api/payments/webhook` routes to the package's `WebhookController`
   which handles HMAC; testing valid/invalid HMAC signatures requires test-mode
   keys or package test helpers; not covered.
5. **[MEDIUM] `PaymentPolicy::initiate` always returns false for
   `MentorProgram`** — BA Story 1 implies program payments should be
   initiatable; the policy currently only allows `MentorSession`. This is an
   undocumented deviation from BA.
6. **[LOW] `ListPaymentHistoryAction` history with actual data** — status
   filter, date filter, mentor-only view, payable label — all require a non-null
   `transaction_status` cast, blocked until bug #1 is fixed.
