# PRD: Розгортання через Dokploy з використанням Docker Compose

## 1. Огляд

Метою є створення надійного пайплайну розгортання для Mentor Wizard Webapp,
використовуючи **Dokploy** як платформу оркестрації та **Docker Compose** для
визначення сервісів. Це налаштування спочатку буде націлене на **Stage**
оточення з готовністю до Production.

## 2. Цілі

- **Автоматизоване розгортання**: Забезпечити розгортання через GitHub Actions.
- **Підтримка Docker Compose**: Використовувати `docker-compose.yml` (або
  спеціальний варіант для продакшену) для визначення стеку застосунку (App,
  Worker, Scheduler, Reverb, Redis, DB).
- **Інтеграція з Traefik**: Використовувати вбудований у Dokploy Traefik для
  зворотного проксі та керування SSL.
- **Розгортання без простою (Zero-Downtime)**: (Ціль) Мінімізувати час простою
  під час оновлень.
- **Ізоляція оточень**: Розділити секрети та конфігурації для Stage/Production.

## 3. Архітектура та компоненти

### 3.1. Інфраструктура

- **Сервер**: Керується Dokploy.
- **Мережа**: `dokploy-network` (Зовнішня Docker мережа, якою керує Dokploy).
- **Проксі**: Traefik (керується Dokploy).

### 3.2. Сервіси

- **App**: Laravel Octane (FrankenPHP), що обслуговує веб-застосунок.
- **Worker**: Воркер черги.
- **Scheduler**: Планувальник завдань cron (Supercronic).
- **Websockets**: Laravel Reverb.
- **Redis**: Кеш та сховище сесій.
- **Database**: PostgreSQL 17 (Керується в межах Compose або зовнішньо?
  _Припущення: Поки що в межах Compose згідно запиту користувача, щоб уникнути
  "монструозних рішень"_).

### 3.3. Пайплайн збірки (GitHub Actions)

1. **Build**: Збірка Docker образу з `docker/php/Dockerfile`.
2. **Push**: Пуш образу в **GitHub Container Registry (GHCR)**.
    - Теги для Stage: `ghcr.io/owner/repo:main` (або `sha-xxxx`).
    - Теги для Prod: `ghcr.io/owner/repo:latest` або `v1.x.x`.
3. **Deploy**: Тригер розгортання в Dokploy через API (webhook), який змусить
   Dokploy стягнути оновлений образ (pull latest).

## 4. Вимоги

### 4.1. Конфігурація Docker

- **Dockerfile**: Використовувати `docker/php/Dockerfile` для продакшн збірок.
- **Compose файл**: Створити `compose.prod.yml`, оптимізований для Dokploy:
    - Прибрати контексти збірки (build contexts) - використовувати
      `image: ${DOCKER_IMAGE}`.
    - Підключити до мережі `dokploy-network`.
    - Додати мітки (labels) Traefik для сервісів `app` та `websockets`.
    - Налаштувати політики перезапуску `restart: always`.
    - Прибрати маунты та налаштування, специфічні для розробки (наприклад,
      локальні томи для коду).

### 4.2. Конфігурація Dokploy

- **Проєкт**: Створити проєкт в Dokploy.
- **Тип**: "Docker Compose".
- **Змінні оточення**: Безпечно зберігати секрети в Dokploy (синхронізувати з
  GitHub Actions або встановити вручну спочатку).

### 4.3. Домен та SSL

- **Домен**: `mentor-wizard.com` (вже зареєстровано).
- **SSL**: Let's Encrypt через Traefik.

## 5. Етапи реалізації

### Етап 0: Секрети та оточення

- Визначити секрети в GitHub Repository Secrets.
- Налаштувати GitHub Environments для Stage/Prod.

### Етап 1: Пайплайн збірки

- Створити GitHub Action workflow для збірки та пушу Docker образу.

### Етап 2: Конфігурація розгортання

- Створити `compose.prod.yml`.
- Налаштувати сервіс Dokploy.
- Реалізувати тригер розгортання.

### Етап 3: Домен та сертифікати

- Налаштувати DNS записи.
- Перевірити випуск SSL.

### Етап 4: Сповіщення

- Додати сповіщення в Slack до GitHub Actions workflow.

### Етап 5: Моніторинг

- Переконатися, що Telescope налаштований належним чином та захищений для
  використання в продакшені.
